# 行业与开源参考资料

访问与核对日期：2026年10月29日。以下材料用于行业判断、功能对比和设计参考。项目能力随版本变化，引用不表示本地已部署或通过实际联调。

## 业务材料

用户提供的 `discovery-report.md`，标题为“澄岳研究院业务需求发现报告”，生成于2026年10月29日。它明确采用合成场景访谈，需求为待验证假设。证据编号 `research-f00` 至 `research-f55` 用于追踪需求，不能把覆盖率或目标值解释为真实业务验证结论。

本项目保留其关键边界：首期一个项目组的境内普通差旅，只读对齐，保留人工签核；付款与银行卡修改不在工具范围内。

## GitHub 方案

| 来源 | 可参考的能力 | 本项目采用方式与边界 |
|---|---|---|
| [Frappe HRMS](https://github.com/frappe/hrms)及[Expense Claim 文档](https://docs.frappe.io/hr/expense-claim) | 费用报销、审批和项目归集 | 参考费用与审批概念；未复制其业务源码，未安装为运行依赖。HRMS 仓库标注 GPL-3.0。 |

| [OCA hr-expense 18.0](https://github.com/OCA/hr-expense/tree/18.0) | `hr_expense_exception` 异常规则和 `hr_expense_tier_validation` 分级审批 | 作为可扩展路线参考，当前未依赖该模块集合。仓库默认 AGPL-3.0，实际许可须逐模块核对。 |
| [Frappe Framework](https://github.com/frappe/frappe) | 业务表单、角色权限、数据模型和 REST 接口 | 作为后续在线应用底座候选，当前标准库 CLI 未采用该框架；框架许可证为 MIT。 |

这些项目证明报销与审批存在可复用方案，但不能据此认定任何一个方案无需改造即可覆盖只读 ERP/OA 对齐、单票多项目追溯、制度版本裁定及本案例交接要求。本项目自行实现较小的离线验证范围。

引用思路不等于复制代码。后续若引入代码，需核对选定提交中的 `LICENSE`、`license.txt`、模块 `__manifest__.py` 及实际依赖，保留适用声明并记录修改。不能用 Frappe Framework 的 MIT 许可推断 HRMS 或其他应用的许可。

## 官方行业资料

1. [财政部等关于推广应用电子凭证会计数据标准的通知](https://www.mof.gov.cn/jrttts/202505/t20250521_3964264.htm)，财会〔2025〕9号，成文于2025年5月9日。支持凭证结构化及接收、报销、入账、归档协同的建设方向；不证明本工具已适配全部电子凭证标准。
2. [国家税务总局关于推广应用全面数字化电子发票的公告](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5236067/content.html)，国家税务总局公告2024年第11号，2024年12月1日起施行。说明数电发票推广背景；公共查验渠道的存在不等于本项目具备可调用的实时验真 API。
3. [会计信息化工作规范](https://kjs.mof.gov.cn/zhengcefabu/202408/P020240805628932632907.pdf)，财会〔2024〕11号。第16—17条涉及审签、自动规则及变更可追溯，第25—26条涉及验证、重复入账防范和数据解析。规范并非禁止全部自动审核；本案例保留人工签核源于业务权限和尚未裁定的规则。
4. [国务院办公厅关于改革完善中央财政科研经费管理的若干意见](https://most.gov.cn/xxgk/xinxifenlei/fdzdgknr/fgzc/gfxwj/gfxwj2021/202108/t20210813_176373.html)，国办发〔2021〕32号，2021年8月5日成文。科研财务助理及无纸化报销安排提供行业背景；具体机构和项目适用范围仍须核实。

本项目不依据这些材料虚构行业市场规模、工具市场占有率或实施收益。合成案例的10万元预算、38%补件率、22分钟重复录入时间及3天目标均不属于行业平均数据。
