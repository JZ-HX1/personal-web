# 贡献指南

本项目用于教学验证差旅报销辅助流程。修改应围绕可复现的业务问题，并保留原始记录、人工确认和已知信息缺口。

## 本地准备

在子项目目录使用 Python 3.10 或以上版本：

```bash
python -m pip install -e .
python examples/demo.py
python -m unittest discover -s tests -v
```

本项目使用标准库 `unittest`，不要求另外安装测试框架。演示脚本可独立运行；可编辑安装用于直接调用包入口。

## 修改原则

1. 先说明触发条件、原行为、期望行为和受影响的命令。
2. 为金额计算、制度适用、事件顺序及导入一致性等业务逻辑补充有意义的测试。
3. 修改输入字段或 CLI 参数时，同步更新样例与 `docs/api.md`。
4. 修改制度规则时使用合成案例，并说明规则版本、有效期、适用范围和人工确认条件；不要写成真实单位已批准制度。
5. 保持“未知”状态，不通过猜测填补标识、审批或付款节点。
6. 引入依赖、外部连接或改变数据存储时，在 PR 中交代用途、许可和现有命令的兼容性。

提交源码和合成样例即可。真实发票、身份证、银行卡、访问令牌以及本机数据库不应作为问题复现材料。需要展示异常时，构造字段相同但不含真实个人信息的最小样例。

## 提交前检查

运行测试和示例，检查其输出与文档一致。对修改的行为记录实际运行命令和结果；没有执行的验证应明确标注，不填写推测结果。

PR 描述应包含业务问题、最终变化、验证结果和尚未覆盖的限制。纯排版或文案修正不需要新增镜像式测试。

## 开源引用

`docs/references.md` 中的外部项目用于能力对比和设计参考。若后续复制或修改外部源码，需在提交前核对该版本和具体文件的许可、保留必要声明，并更新引用记录。不能用框架许可推断其应用及扩展模块的许可。

## 父仓库集成

本目录可独立开发和测试。修改 `JZ-HX1/personal-web` 的网站、根目录自动化或仓库设置应作为独立变更说明。这里的 `.github` 模板位于子项目内，GitHub 不会将它们自动识别为父仓库的模板。
